## 0. Summary

1. **C2 works, with one correction and one cost.** All five spike items came out as the inventory hoped (§1). The **correction**: a theme registered at runtime must carry `variables: {}` or Vuetify throws inside `app.use(vuetify)` and the whole app never mounts (a blank page). The **cost**: if registration runs at module load (as in the spike), the **creator web's Vuetify theme stylesheet grows by about 6.7 KB** of inert rules (`18863` to `25525` characters) even though its DOM and computed styles are identical. Registering inside `AgencyLayout`'s `setup()` would avoid it. That is the first gate of step S1.1 (§3).
2. **The Roboto fallback is real, and it is bigger than the inventory said.** Every `text-*` element renders in `Roboto, sans-serif` (not installed here, so the system sans), **and so does everything inside a teleported overlay** (menus, selects, dialogs), because `html` and `body` are Roboto and only `.v-application` is Inter. Both fixes are agency-scoped and were shown to work (§1.4). Creator web has the same bug; it stays out of scope (AH-115).
3. **Overlays inherit the agency theme class.** Menu, dialog and select overlays all carried `v-theme--agency-dark` and the agency surface colour (§1.2).
4. **Agency to creator leaves nothing behind.** Computed-style hash and DOM identical to the clean baseline; zero agency classes; no `html` or `body` residue (§1.3).
5. **The seven specs** from inventory §7.3 sit in the layer they protect (§4). Two change shape against the inventory text and are flagged (spec 1 gains one allowed selector form; spec 5 becomes a content-hash pin because ruling 9 (a) means no shared file is edited).
6. **Six layers, 27 steps** (§3): L0 guards, tokens and themes (nothing renders differently) → L1 shell and primitives → L2 status pill and four forks → L3 the four designed pages → L4 inference over the other agency routes → L5 close-out. Deploy is one web build at the end (§6).
7. **Points for the plan review** are in §8 (nine; the ones that change scope are P1, P2 and P5).

### 1.4 Items 4 and 5: `html` / `body` background, and the font — both need agency-side fixes

**`html` / `body` background (MEASURED).** In agency dark, `html` and `body` backgrounds are `rgba(0, 0, 0, 0)` and `html` has `color-scheme: dark`. The visible dark comes from `.v-application`. So whatever shows outside it (overscroll, the strip behind a short page, the canvas colour at the window edge) is the browser's own dark canvas, not `#0b0b0c`. The actual overscroll pixels were **not** looked at (NOT PROVED; the computed value is). **Fix proved in-page:** `:root:has(.v-application.v-theme--agency-dark) { background-color: … }` (and a light twin) made `html` compute `rgb(11, 11, 12)` on agency, went back to `rgba(0, 0, 0, 0)` after navigating to the creator route, and came back on returning. One trap found on the way: `rgb(var(--v-theme-background))` on `html` resolved to the **global** dark theme (`9, 9, 11`), because the agency variables live on the layout element, not on `:root`. So the canvas rule must define its own value, from the same token source, inside the rule.

**Font (MEASURED).**

| Element                                               | Before the fix               | After the scoped fix                                                                                     |
| ----------------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| `h6.text-h6` (`.v-application`)                       | `Roboto, sans-serif`         | `Inter, system-ui, -apple-system, sans-serif`                                                            |
| `p.text-body-2`                                       | `Roboto, sans-serif`         | `Inter, system-ui, -apple-system, sans-serif`                                                            |
| The `.v-application` root itself                      | `Inter, system-ui, …` (fine) | unchanged                                                                                                |
| `html`, `body`, `.v-overlay-container`, every overlay | `Roboto, sans-serif`         | overlay fixed by `….v-overlay { font-family: var(--brand-font-primary) }` under the agency theme classes |

Canvas text-width probes agree: Roboto, the generic sans and Arial all measure 246.8 px for the test string while Inter measures 257.71 px, so Roboto is not installed on this machine and the fallback is the system sans. **The Roboto fallback is real, it is in scope on the agency side, and the fix has two parts**: (1) the `.text-*` utilities under the agency theme classes (`!important`, with the theme-class prefix so specificity wins whatever the load order), (2) the overlay font. A production build was not run, so the cascade order against Vuetify's built CSS is **NOT PROVED**; the prefix makes the result independent of order, and S1.1 re-measures on a built bundle.

The screenshot tool returned stale or mid-transition frames for three of four captures (they show the previous state); DOM and computed-style reads carry every claim above. Real screenshots start at S1.2, with real pages. The storage key and the preference logic were exercised, not the toggle UI (ThemeToggle flip was not run).

## 5. Standing gates (every step, and what "done" means)

3. **No forbidden edit.** `git diff --stat <base>..HEAD` over the §3 ground-rules paths is empty at each step, and specs 3 and 5 are green and **never edited** after S0.1.

The screenshot tool returned stale frames in the spike, so each capture is confirmed against a DOM read taken in the same step; a screenshot that disagrees with its read is retaken, not trusted.
6. **Evidence labels** on every claim in a commit message or review note; "not read" is written as "not read".
7. **Stop gates still apply**, none expected: i18n keys (S2.1 only if a key is unavoidable), and anything that would need an API or contract change is **not built** and goes to §7.
8. **Alarm rule** (`WORKING-PROCESS.md` §6): if a creator hash moves, a shared file hash moves, or a step needs an edit in the forbidden list, stop and report; do not work around it.
